# Лабораторная работа №2 — Online Retail в Apache Spark

Java-приложение загружает CSV датасета **Online Retail**, проверяет и очищает
данные, после чего формирует топ-5 товаров и клиентские показатели. Spark
запускается локально внутри Docker-контейнера (`local[1]` для ВМ с 1,6 ГБ RAM).

Источник и схема данных: [UCI Online Retail](https://archive.ics.uci.edu/dataset/352/online+retail).

## Что выполняет программа

1. Читает `data.csv` в кодировке Windows-1252 и разбирает все восемь полей,
   включая значения с запятыми и переносами строк в кавычках.
2. Удаляет полные дубликаты по исходным восьми полям до преобразования типов.
3. Преобразует `Quantity` в `long`, а `UnitPrice` — в `BigDecimal`.
4. Проверяет формат номера документа, обязательные поля, знаки количества и
   цены, а также отсутствие связи одного заказа с несколькими клиентами.
5. Отделяет обычные продажи от возвратов и отклонённых строк.
6. Исключает служебные коды только из товарного рейтинга.
7. Выгружает топ-5 товаров, суммы заказов и метрики всех известных клиентов.

В основных витринах используется **gross-подход**: возвраты не уменьшают сумму
продаж. Строки без `CustomerID` участвуют в рейтинге товаров, но не могут быть
включены в клиентскую статистику. Клиентская сумма включает допустимые платные
служебные позиции (например, доставку), а товарный топ — нет.

## Структура кода

| Класс | Ответственность |
|---|---|
| `RetailApp` | точка входа и последовательность этапов |
| `DatasetLoader` | чтение файла, дедупликация и типизация |
| `CsvParser` | корректный разбор CSV |
| `Transaction` | типизированная строка датасета |
| `DatasetValidator` | правила качества, продаж и возвратов |
| `ProductAnalytics` / `ProductMetrics` | топ товаров |
| `CustomerAnalytics` / `CustomerMetrics` | заказы и показатели клиентов |
| `ResultWriter` | сортировка и запись CSV-результатов |

Подробный контракт обработки и принятые допущения находятся в
`DE_memo.md`. Этот файл при доработке программы не изменялся.

## Запуск через Docker Compose

Требуются Docker и Docker Compose. Датасет должен находиться в корне проекта
под именем `data.csv`.

```bash
docker compose build
docker compose run --rm online-retail-loader
```

Перед повторным запуском следует удалить созданный ранее каталог `output`,
поскольку Spark не перезаписывает существующие каталоги результатов.

Можно также запустить собранный образ с другими путями:

```bash
docker run --rm \
  -v "$(pwd)/data.csv:/data/input.csv:ro" \
  -v "$(pwd)/output:/output" \
  online-retail-loader:lab2 \
  --master 'local[1]' --class ru.example.RetailApp \
  /opt/spark/work-dir/online-retail-loader.jar /data/input.csv /output
```

## Результаты

Spark создаёт каталоги с одним `part-*` файлом и заголовком:

- `output/top5_products.csv` — пять товаров по суммарному количеству;
- `output/orders.csv` — сумма каждого заказа известного клиента;
- `output/customer_metrics.csv` — число заказов, общая сумма и средний чек.

Проверочный запуск на полном датасете дал следующие контрольные значения:

| Показатель | Значение |
|---|---:|
| Исходные строки | 541 909 |
| Уникальные строки | 536 641 |
| Удалённые дубликаты | 5 268 |
| Допустимые строки продаж | 524 877 |
| Заказы известных клиентов | 18 532 |
| Известные клиенты | 4 372 |

Топ-5 по общему количеству проданных единиц:

| StockCode | Количество | Заказов с товаром | Gross, GBP |
|---|---:|---:|---:|
| 23843 | 80 995 | 1 | 168 469.60 |
| 23166 | 78 033 | 247 | 81 700.92 |
| 22197 | 56 898 | 1 392 | 51 334.47 |
| 84077 | 54 951 | 535 | 13 814.01 |
| 85099B | 48 371 | 2 089 | 94 159.81 |

`average_order_value` вычисляется как `total_spent / orders_count` и только при
выгрузке округляется до двух знаков по правилу HALF_UP. Для клиентов без продаж
число заказов и сумма равны нулю, а средний чек остаётся пустым.
